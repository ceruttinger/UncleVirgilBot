About this Project

Project overview

Uncle Virgil Bot is a digital humanities project built around a memoir written by Virgil Harris, my grandfather’s brother. The memoir has been converted into a structured text corpus so it can be explored through reading, search, textual analysis, named entities, graphs, and a model-backed question-answering prototype.

This project treats the memoir as both a family-history document and a research corpus. The site preserves access to the source scans while also creating derived data products that make the memoir easier to analyze.

What the site includes

Memoir text and scanned source material

The chapter pages provide readable text derived from the OCR/RDS source files. The scanned PDFs remain available so readers can compare the extracted text against the original pages.

Timeline

The timeline uses curated chapter-level date ranges along with detected year candidates from the text. This helps separate a chapter’s main life period from historical references, later reflections, and background dates.

Sentiment analysis

The sentiment layer shows overall positive/negative tone by chapter and sentiment shifts within each chapter. It is useful for seeing where the memoir becomes more reflective, difficult, affectionate, institutional, or event-driven.

Emotion analysis

The emotion layer uses lexicon-based categories such as anger, anticipation, disgust, fear, joy, sadness, surprise, trust, positive, and negative. These should be read as exploratory signals rather than psychological claims. They show where certain kinds of emotionally coded language cluster in the memoir.

Named entities

The entity layer identifies recurring people, places, organizations, dates, and events. This makes it easier to follow major figures, family members, geographic movement, institutional settings, and historical references across chapters.

Entity graph

The entity graph turns the memoir into a network. Chapters connect to the people, places, organizations, events, and dates they mention. This makes it possible to explore questions like:

  • Which chapters share the same people or places?
  • Where do family, military, church, education, and government work overlap?
  • Which entities anchor different life stages?
  • Which historical contexts appear across multiple chapters?

The graph is not meant to be a final scholarly interpretation. It is a navigation and discovery tool.

Passage index

The passage index breaks the memoir into smaller citation-ready units. Each passage has a chapter, passage number, source label, detected years, and linked entities. This provides the retrieval layer for search and model-backed answers.

Ask Uncle Virgil

The model-backed prototype retrieves relevant passages and sends them to an AWS-hosted model. The model then produces an answer grounded in the retrieved passages and lists the source labels underneath. This keeps the AI layer connected to the memoir rather than letting it answer from general knowledge alone.

How to interpret the analysis

The analysis pages are exploratory. OCR artifacts, spelling variation, historical language, and the limits of lexicon-based methods can affect the results. The strongest use of the site is comparative: reading across chapters, checking source passages, and using the graph and passage tools to discover patterns worth closer human interpretation.

Technical approach

The project is built as a static Quarto website with generated data files. The source text is processed into chapters, passages, sentiment tables, emotion tables, entity registries, graph nodes and edges, and search indexes. The static pages run on GitHub Pages. The experimental model-backed page uses an AWS Lambda endpoint, S3-hosted passage data, and Amazon Bedrock.
